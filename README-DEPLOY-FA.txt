راهنمای نصب نسخه آماده‌شده
========================

این نسخه برای انتقال از GitHub Pages به هاستی که برای کاربران شما در ایران در دسترس است آماده شده است. تغییر DNS و انتشار روی هاست از داخل این فایل انجام نمی‌شود.

1) انتشار سایت
- محتوای همین پوشه را در ریشه سایت هاست (معمولاً public_html) بارگذاری کنید؛ فایل index.html باید مستقیماً در ریشه باشد.
- از شرکت هاست، IP یا رکوردهای DNS مخصوص دامنه را بگیرید. پس از بارگذاری و بررسی سایت روی آدرس موقت هاست، رکوردهای دامنه را طبق راهنمای همان شرکت تغییر دهید و HTTPS را فعال کنید.
- فایل CNAME مخصوص GitHub Pages در این بسته نیست.

2) فایل‌های محلی
- Tailwind، Swiper، AOS، Font Awesome و فونت Vazirmatn در assets/vendor نگهداری می‌شوند و دیگر برای ظاهر و اسلایدرها از CDN خارجی بارگیری نمی‌شوند.
- نقشه Google در صفحه و سرویس Firebase همچنان وابستگی خارجی هستند. اگر دسترسی به Google/Firebase در شبکه کاربر قطع باشد، نقشه ممکن است نمایش داده نشود و فرم ارسال سوال پیام عدم دسترسی می‌دهد. برای ارسال فرم بدون فیلتر باید backend روی هاست جدید یا سرویس قابل‌دسترسی دیگری تنظیم شود.

3) پنل سوال‌ها و Firebase
- در Firebase Console، Authentication را باز و ورود Email/Password را فعال کنید.
- برای مدیر یک حساب بسازید. در پنل با همان ایمیل و رمز وارد شوید.
- محتوای firestore.rules.template را در Firestore > Rules قرار دهید و ADMIN_EMAIL_REPLACE_ME را با ایمیل دقیق مدیر جایگزین کنید؛ سپس قوانین را منتشر کنید.
- اگر قوانین را منتشر نکنید، فرم عمومی می‌تواند سوال ثبت کند ولی پنل اجازه دیدن/مدیریت سوال‌ها را نخواهد داشت. خود کد پنل جایگزین قوانین سمت سرور نیست.

4) هشدار کلید GitHub
- کلید Firebase در js/firebase.js به‌عنوان شناسه عمومی وب Firebase باقی مانده؛ این برنامه عمداً آن را از کلاینت حذف نمی‌کند چون Firebase برای تماس‌های مرورگر به آن نیاز دارد.
- در Google Cloud Console بررسی کنید کلید، Browser key مربوط به همین پروژه باشد و فقط برای Firebase APIs محدود شده باشد. قوانین Firestore باید دسترسی داده‌ها را کنترل کنند.
- اگر همان کلید برای Google API دیگری استفاده شده، یا در تنظیمات محدود نیست، آن را در Google Cloud محدود/تعویض کنید و مقدار جدید را در js/firebase.js قرار دهید.
- بعد از بررسی، هشدار GitHub را با توضیح اینکه کلید، Firebase Web API key عمومی است ببندید. حذف فایل یا بستن alert به‌تنهایی کلید را باطل نمی‌کند.

5) فایل‌های وابستگی
- نسخه و منبع فایل‌های محلی در assets/vendor/SOURCES.txt ثبت شده است.
